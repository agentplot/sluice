## Context and problem statement

A place's scratch directory, the one path besides its checkout and the host's declared caches that a confined check may write (35, C.4), is `<git common dir>/sluice/.tmp/<dir name>`, where the dir name is the place's name with its slashes escaped, shortened only past 246 bytes. A session's place is named `session/<the worktree's full path>`, so its scratch path holds the worktree's whole location twice over, escaped, and grows with every directory above the worktree and with the worktree's own name. The plugin's lay-out suite makes a scratch clone under `SLUICE_TMP` and drives Claude Code in it, whose project key is the clone's path with every other character made a dash and is refused past 200 characters; on deneb two of sluice's own worktrees give 201 and the suite refuses to start, so the gate cannot be run from them before submitting. A Unix socket bound under the same path would fail sooner, at macOS's 104 bytes. Trimming the suite's own names wins a few characters and no worktree.

## Considered options

1. The scratch at a path that does not grow with the place's name or its checkout's location: under the repository's own `sluice/.tmp/`, named by a short fixed-length digest of the place's name, as `SLUICE_PLACE` already names the place (`sluice-<10 hex>`); the place's record names the path, so a release, a stored one among them, removes what the record names, and scratch no record names is an abandoned place's (123).
2. Shorten the suite's own names so today's worktrees pass.
3. The scratch under the checkout, in an ignored directory.
4. The scratch under the host's state directory, `$XDG_STATE_HOME/sluice`, apart from the repository.
5. (2026-11-03) The scratch under a short directory of the host user's own, apart from every repository: the real path of `/tmp/sluice-<uid>/`, then 10 hex digits of a digest of the repository's git common directory, then option 1's name for the place.
   - For the directory on Linux, `$XDG_RUNTIME_DIR/sluice/` where it is set, as the change's brief proposed.
   - For the directory, `$TMPDIR`.
   - For the repository's key, a key made once and kept in the repository's state.
   - (2026-11-05) For a worktree's place made before, its former scratch kept until `sluice release`, as from 2026-11-03 to 2026-11-05.
   - (2026-11-05) For a worktree's place made before, a fresh short scratch at its next run and the former one removed, wherever the system could move it.

## Decision outcome

Option 1 until 2026-11-03; option 5 from then, which keeps option 1's name for a place and its record naming the path, and moves the root.

**The limit is a check's, and every check meets it.** The sandbox lets a check write its checkout, its scratch and the declared caches and nothing else (35, C.4). What a check makes under its scratch, a socket, a clone, a tool's state keyed by its path, meets the limits of the tools the repository's checks run: 104 bytes for a socket on macOS, 200 characters for the key the suite met. A scratch whose path carries the worktree's location breaks those limits for a worktree of a long enough name or a deep enough home, and the check's author can do nothing about it from inside the check. A fixed-length name under a fixed root gives every check the same room whatever the place is called or where it lives.

**The record names the path, so nothing is left behind.** Today the scratch path is derived from the place's name each time it is wanted and the record does not carry it. With the name's scheme changed, a release of a place made before the change would derive a path the old scheme never made. So the record names the scratch path, written when the place is made; a release, run at once or stored (123), removes the path the record names, however the name was made; and a directory under `sluice/.tmp/` no record names is an abandoned place's, removed as 123 removes a gone place's. Nothing reads a name back from a path (`shortened`'s own rule), so the digest need not be reversible.

**Where it lives (amended 2026-11-03).** The repository's location is no more the check's to choose than its worktree's. Under the repository's own `sluice/.tmp/` the scratch grew with where the repository lives, 73 bytes on one host, which left a tool 31 bytes for the sockets it keeps in a folder of its own under the scratch. A short directory of the user's own, the same for every repository on the host, gives every check the same room on every host: `/private/tmp/sluice-501/`, the repository's 10 hex digits and the place's is 45 bytes on macOS, and the same under `/tmp/sluice-1000/` is 38 on Linux. Option 3 would put a check's scratch inside the tree the check is judged on, where `git status` must stay clean and a submit would carry it; option 4's state directory grows with the home's path; option 2 is the suite's workaround for one host's worktrees and leaves every other check, and every socket, where it was.

**The directory is `/tmp`'s, resolved, on every system (2026-11-03).** `/tmp` is short, every process of the user sees the same one, and it is where a check's temporary files belong, which under the sandbox are its scratch's: the sandbox gives a check its scratch as `TMPDIR`, so builds and clones are written there. The path is resolved before it is written on a record, since Seatbelt matches resolved paths and `/tmp` is `/private/tmp` on macOS, so the record, `SLUICE_TMP`, `TMPDIR` and the sandbox's rule name one path and a socket bound under it is the sandbox's to allow. `$XDG_RUNTIME_DIR` is not used, even where it is set: the XDG Base Directory specification keeps it for small files, lets it live in memory with a size limit and be cleaned, and it is unset for a process outside a login session, so two processes of one user, a session's and a service's, would disagree on where a repository's scratch is. `$TMPDIR` on macOS is the user's folder under `/var/folders`, 49 bytes before anything of sluice's. A system may empty `/tmp` when it restarts or by its own cleaning, so a scratch, its repository's directory and the user's directory are made again wherever a run or a release wants a scratch and finds it gone; a check keeps nothing in its scratch it cannot make again.

**The directory is the user's own (2026-11-03).** `/tmp` is every user's, and another may have made the name first. `/tmp/sluice-<uid>` is made readable, writable and searchable by its user alone, as a terminal multiplexer makes its own sockets' directory; one that already exists and is not a directory of the user's own, closed to everyone else, a link among what is refused, is refused with its path and what is wrong, never used, changed or removed, and nothing of a place is made under it. The repository's directory under it is made the same way.

**Each repository has its own key, from where it is (2026-11-03).** The repository's directory under the user's is named by 10 hex digits of the SHA-1 of the real path of its git common directory, made in process as option 1's name is. Two repositories at two paths get two keys, a copy of one included; a key made once and kept in the repository's state would be copied with it, and each copy's sweep would remove the other's live scratch. A repository moved takes a new key for the places it makes next, and its places' records still name their scratch, which they are released at.

**The sweep reaches only the repository's own (2026-11-03).** Scratch no record names is an abandoned place's (123), among the scratch the repository's places made: the sweep lists the repository's directory under the user's, never the user's directory itself, so it never weighs another repository's scratch, and the repository's former root, `sluice/.tmp/`, where places made before keep their scratch, by the same rules as before. Where the user's directory is refused as above, the sweep removes nothing under it and says so, and still sweeps the former root.

**A worktree's place made before takes the short path at its next run (2026-11-05).** A worktree's place lives as long as its worktree, so a place an older sluice made would keep its scratch under the repository's `sluice/.tmp/` for as long as an agent works there, and every run of it would meet the limits this record exists to lift. At its first run with none of its runs going, its record is made to name the short path, and its former scratch is moved there by a rename, what its checks keep between runs going with it. Where the system cannot move it, the short path is made and the former scratch removed: a check keeps nothing in its scratch it cannot make again, as a system emptying `/tmp` already asks of it; a fresh scratch on every host would discard what the rename keeps where it can. While a run of it is going, that run was given the former scratch and its sandbox writes that path alone, so the place keeps it until no run of it is going. A candidate's place is made for one run and a preview's for one command, whose stack may keep what it handed off in its scratch, so either made before keeps its scratch where its record names until it is released.

**A host takes it when its sluice is updated.** The scratch is made by the sluice installed on the host, so the suite's guard stands on a host until its sluice carries this record; the guard says why it refuses, in the terms above. A host whose sluice predates the amendment keeps making scratch under `sluice/.tmp/`; it reads a newer record's path as any record's, and its sweep lists only `sluice/.tmp/`, so a host running both never has one remove the other's.

### Consequences

- The place profile names a place's scratch by the real path of `/tmp/sluice-<uid>/`, the repository's key and a short fixed-length digest of the place's name, writes the path on the place's record when the place is made, and removes the path the record names on release; a record with no scratch path is a place made before 2026-10-27, whose scratch is at the path the former scheme gave it, and a record naming one under `sluice/.tmp/` is a place made before 2026-11-03; a candidate's or a preview's such place is released there, and a worktree's is moved to the short path at its first run with none of its runs going.
- The user's directory and the repository's under it are made closed to everyone but the user, and are refused where they exist and are not.
- A directory under the repository's directory in the user's, or under its former `sluice/.tmp/`, that no record names is removed with the abandoned places (123); no other repository's is weighed.
- The sandbox profile and the check seam take the scratch as the place gives it and change nothing; the container executor, not built, gives its container the scratch its place's record names when it is.
- The lay-out suite's guard stands until the host's sluice carries this record; the chore `the-lay-out-suite-runs-from-any-worktree` becomes the unit that builds it. The change `a-places-scratch-is-under-a-short-directory-of-the-host-users-own` builds the amendment of 2026-11-03.
- Rule core.30 is drawn from this record; clause 35 of the statement says the same.
