# Tasks

The groups land in order, as one landing, from this change's place on
`change/the-herdr-plugin-keeps-one-watcher-per-host`. Every task is in
`plugins/herdr`, whose checks are the moon project `plugin-herdr`'s
tasks: `test-sh` runs `tests/run.sh` under the system's sh, `test-dash`
runs it under dash where dash is installed, and `manifest` runs
`tests/manifest.sh`. `tests/run.sh` runs every test in one pass, so a
task's check is the project's task, and the task names the tests in
`tests/run.sh`, by the names `fresh` gives them, that must be there and
pass. Run it through sluice (`sluice exec main -- moon run
plugin-herdr:test-sh`). Tests use scratch repositories and the
stand-in `herdr` and `sluice` under `tests/fake`. They never reach a
running herdr, the host's sluice state or a network. Commit by
pathspec, with Conventional Commits scoped `plugins/herdr` or `site`,
citing records 0094, 0023 and 0056 by number and the design's decisions
by D-number.

## 1. The host's state and each server's

Stand-in `jq` and `git` log each call and pass it on to the real one while a test asks them to, as the stand-in `sluice` logs its calls today. The tests run their servers at socket files in their scratch folder, and the suite's helpers read the host's state (D2, D3). True when `sluice exec main -- moon run plugin-herdr:test-sh` passes with every test that passes today.
- [x] 1.2 `lib/common.sh` names the host's state (`state`) and the folder of the server in the environment (`server`). The documents, learned paths, blamed tests, forecasts, probes, the popup's asks, the problem and the lease are the host's. A server's socket, herdr, link, tokens, `seq` and panes are its own (D3). True when `sluice exec main -- moon run plugin-herdr:test-sh` passes, with `watch: read by every server` added.
- [x] 1.3 `segment.sh` reads the host's documents with nothing of its environment but `HOME` and `PATH`. The watcher refreshes the segment's copy at its start, not at each event (D12). True when `sluice exec main -- moon run plugin-herdr:test-sh` passes with `status: the segment is the server's`, run with `HOME` and `PATH` alone, and `status: the segment is the same in every server`.

## 2. One watcher per user on a host

- [ ] 2.1 The lease is the host's `watch.lease`, naming the watcher's pid, its identity, the plugin folder and the version. Its lock is beside it, and nothing renews it. `--ensure` registers its server in `servers/<sum>/` (`socket`, `herdr`, a hard link where one can be made). It sends `USR1` to a live watcher of this folder and version, else starts one. A watcher that finds the lease held by another live process of its own folder and version exits (D1, D2). True when `sluice exec main -- moon run plugin-herdr:test-sh` passes with `watch: started twice`, `watch: two servers, one watcher`, `watch: watcher gone`, `watch: a reinstalled plugin replaces its watcher`, `watch: a lock left by a watcher that died` and `watch: a lock with no owner`. `watch: a long tick keeps the lease`, `watch: a renewer killed holding the lock` and `watch: one watcher per herdr server` leave the suite with the renewer and the per-server lease.
- [ ] 2.2 The watcher calls each registered server through its own socket and herdr. At a tick it drops a server whose socket is gone or is not its link's file. It also drops one whose calls failed twice in a row. It stops with its sources and releases the lease once it serves none (D2). True when `sluice exec main -- moon run plugin-herdr:test-sh` passes with `watch: herdr stops`, `watch: one of two servers stops`, `watch: another herdr server in its place` and `watch: herdr gone`.
- [ ] 2.3 A watcher whose folder's `herdr-plugin.toml` is gone or newer than its lease gives way at its next tick. One that reads another pid in the lease stops with its sources (D1). True when `sluice exec main -- moon run plugin-herdr:test-sh` passes with `watch: a plugin put back stops the host's watcher`.
- [ ] 2.4 At its start, the host's watcher removes each former `servers/<sum>/watch.lease`. Once their holders have ended, or after two ticks, it ends the sources a killed former watcher listed, by their identity, and removes each server's former folders, keeping each `watch.log` (D11). True when `sluice exec main -- moon run plugin-herdr:test-sh` passes with `watch: a former version's watchers give way`.
- [ ] 2.5 The README and the site's herdr guide say the plugin keeps one watcher for a user's herdr servers on a host, with one overview watch for each repository a pane of any server is in. No gate reads the README, which is `*.md` outside the site (core.21), so it is read against the specs by hand. True when `sluice exec main -- moon run site:prose` passes.

## 3. Nothing forked while nothing changes

- [ ] 3.1 The watcher waits in `wait` on its tick's one `sleep`. `USR1` wakes it, sent by an ensure, a reader that kept a document, a reader whose source ended, and the popup's ask, each leaving its marker. After a wake it waits on the same `sleep`. A tick uses builtins alone unless one of them found a change (D4, D5). True when `sluice exec main -- moon run plugin-herdr:test-dash` passes with `watch: idle ticks run nothing` and `watch: a change wakes it`. dash is where a trapped signal's end of `wait` is strictest. `test-sh` runs them under the system's sh at verify.
- [ ] 3.2 Every fourth tick, the minute's pass runs for each server whose `tokens.json` holds a token. It lists that server's panes once, computes its tokens once, and reports each one changed or shown. A server that shows none has no pass (D5, D6). True when `sluice exec main -- moon run plugin-herdr:test-sh` passes with `sidebar: a shown token is set again once a minute`, `sidebar: tokens fade without the watcher` and `sidebar: landed, then gone`.
- [ ] 3.3 At each look the watcher keeps each worktree's git folder. At each tick it tests `HEAD` and `logs/HEAD` there against `checks/<sum>.stamp` with `-nt`, a time equal to the stamp's counting as moved. A moved head gets its count and forecast at that tick (D10). True when `sluice exec main -- moon run plugin-herdr:test-sh` passes with `sidebar: a commit is forecast within a tick` and `sidebar: nothing changed`.

## 4. One read of each repository

- [ ] 4.1 The look takes the repositories in every server's kept panes, with the popup's asks, and starts the default source once for each repository with records. It stops the source of a repository no pane of any server is in, and removes that repository's document, learned paths, blamed tests and told list. A source of the user's is never stopped for want of panes (D7). True when `sluice exec main -- moon run plugin-herdr:test-sh` passes with `watch: panes of two servers in one repository`, `watch: the last pane leaves`, `watch: no configuration` and `watch: a source of the user's`.
- [ ] 4.2 A source is `( cd "$where" && exec <command> ) | reader &`, its command's pid and identity kept as today. The reader marks its source ended at its input's end and signals the watcher, which restarts it at the next tick (D7). True when `sluice exec main -- moon run plugin-herdr:test-sh` passes with `watch: source exits`, `watch: three servers, two repositories, six processes`, `watch: a killed watcher's sources are ended`, `watch: a watcher stops only its own sources` and the tests of a source known without `ps`.
- [ ] 4.3 The reader hands each line to one `jq` with the told list, learned paths and blamed tests. It writes what that `jq` says to keep by redirection and `mv`. It runs `sluice status` only to learn a blamed or conflicting submission, and herdr only to tell. The events told are `told/<key>.json`, a missing list being a first sight (D8). True when `sluice exec main -- moon run plugin-herdr:test-sh` passes with `watch: a large document costs what a small one does`, `watch: two documents`, `watch: a document missing fields`, `watch: a document it cannot read`, `watch: what a held place failed is kept to its last line`, `toasts: watcher restarted`, `toasts: first sight of a repository`, `toasts: what is told is kept only while it is recent`, `toasts: an event on a long branch, or of many submissions` and `toasts: none when what was told cannot be kept`. `toasts: two watchers tell an event once` leaves the suite, since one watcher keeps the list.
