# Tasks

Each group is one session's work for an implementer who reads this
change (proposal, design, specs) and its own group. The groups land in
order, as one landing. Work in this change's place on its branch, cut
from main. Run suites through sluice (`sluice exec main -- cargo test
...`); a quick `cargo check`, `cargo clippy` or one unit test may run
directly. No test reaches a credential or the host's own sluice state:
set `XDG_STATE_HOME` to the test's scratch directory, as the tests do
now, and give every sluice a test starts `support::isolated`. A test
that needs `proto` or `moon` to behave a certain way writes stand-ins
for them in its scratch directory, and a toolchain of its own that puts
them on the path (design, "Tests, and where each scenario is held"). It
never downloads anything. Commit by pathspec (`git add <paths>; git
commit -m "<subject>" -- <paths>`), Conventional Commits, scoped to the
part of the tree, citing clauses by number and rules by id. At least one
commit of the change is a `feat`, so the release CI makes from the
landing is a new minor version. Every group ends with its check task
passing.
