# Tasks

Work in this change's place on its branch, cut from
`bolt/sluice-takes-its-forge-token-from-a-command`, which is its base.
A unit test by name, or one test of `--test forge` over the fake API,
runs directly. A test of the `tools` feature runs through
`sluice exec bolt/sluice-takes-its-forge-token-from-a-command -- …`, as
CLAUDE.md's Running checks has it, and so does each moon task named
below. A test's credential command is a script the test writes into its
own scratch directory with mode `0755`. It begins `#!/bin/sh`, and it
writes what it was asked into files beside it. No test runs a tool of
the family, and none reads the host's own settings or state. Commit by
pathspec, with Conventional Commits subjects scoped to the part of the
tree touched, citing clause 134, record 0108 and the rules by id.

## 1. The credential command

- [x] 1.1 In `crates/sluice/src/identity.rs`, add `CredentialCommand`, `Asked`, `Given` and `COMMAND_LIMIT`, and `CredentialCommand::new(program, args)`, `limited(self, Duration)` and `get(&self, &Asked) -> Result<Given>`, as design D2 gives them. The command runs with its arguments and then `get`, with no shell, in its own process group. Its standard input is written and closed, and its standard output and standard error are each read on a thread of their own, up to 64 KiB. `password` and `password_expiry_utc` are read, and every other key is passed over. `Display` shows the program and its arguments. The recorded arguments are `--app sluice get`, and the recorded input holds the three lines, then a blank one. This is the forge-identity spec's "The command asked as a credential helper". True when `cargo test -p sluice --lib a_credential_command_is_asked_as_git_asks_a_helper` passes.
