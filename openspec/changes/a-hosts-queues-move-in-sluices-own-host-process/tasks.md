# Tasks

The groups land in order, as one landing on
`bolt/sluice-runs-one-host-process`, from this change's place on
`change/a-hosts-queues-move-in-sluices-own-host-process`. Each task
leaves the tree building and its named tests passing. A quick test runs
directly with `cargo test`. A test that starts the binary, git or a
host process runs through sluice against the bolt, as CLAUDE.md's
"Running checks" has it: `sluice exec bolt/sluice-runs-one-host-process
-- cargo test …`. Several names after `--` run each test whose name holds
one of them. New tests on disk go in `crates/sluice/tests/host_process.rs`,
a test target of the fast tier built on `support::OnDisk`, with the
`command` runner and real git. Commit by pathspec, with Conventional
Commits scoped `seams`, `core`, `fakes`, `cli`, `site`, `plugins/sluice`
or `docs`, citing the clauses (135, 129, 71, 150), rules core.31, core.25
and core.49, records 0093 and 0087, and the design's decisions by
D-number.

## 1. A run's room is held from its count to its start

- [x] 1.1 `sluice-seams` gains `RunKind` (`Queue`, `Session`) and `Part`, a run's room in the host's bound, opaque to the core, that gives its room back when dropped. `Tests` gains `hold(&self, kind: RunKind) -> Result<Option<Part>>`, and `start` takes the part: `start(&self, request: &RunRequest, part: Part)`. The fakes' `Tests` holds a part while the parts it holds and the runs it runs are under its bound, and frees it when the part is dropped or the run ends (D12; record 0087). True when `cargo test -p sluice-fakes -- a_part_is_refused_at_the_bound a_dropped_part_frees_its_room` passes.
- [x] 1.2 `choose_starts` holds a part for each run it would mark starting, the runs opened again first, then the window's, before the decision is written. Where `hold` gives none, it marks no further run starting. The round keeps its parts through its landings, releases and outcomes, and `perform_starts` hands each to `start_run`. `capacity` and `starting_here` leave the decision, and so does `perform_starts`'s second reading of `running()`. A run marked starting with no part, a stopped round's, is opened again by the next round. `start_claimed` holds the part its start takes. `start_session` takes the part its caller holds (71; core.49; D12). True when `cargo test -p sluice-conformance --test places -- a_run_decided_holds_its_room_until_it_starts a_run_no_room_was_held_for_is_not_marked_starting a_place_made_by_a_step_that_stopped_before_its_run_started_is_released` passes. The first test holds the fakes' one run from the decision through a landing the same round makes, and a session's `hold` asked during that landing is refused.

## 2. The host's room in one place

- [x] 2.1 `crates/sluice/src/host_process/room.rs` holds `Room`: the host's count, the parts it holds, the runs waiting with their kinds and times, and whose turn the next contested run is. It admits as record 0087 decides. A combination's part is held where a run is free, unless that run is one a session may take, a session's or a preview's run waits, and the turn is the sessions'. A session's or a preview's part is held where a run of the bound less `reserved` is free and is owed to no one, and the turn then passes. A refusal records or renews a wait, and a hold removes it. A combination's wait lapses thirty seconds after its last ask, and a session's when its asker lets it go. Its `waiting()` gives the reason a session's run waits (150, S75; D12). True when `cargo test -p sluice --lib host_process::room` passes with `a_combination_takes_a_free_run_before_a_waiting_session`, `the_next_contested_run_is_a_waiting_sessions_after_a_combination_took_one`, `s75_turns_on_a_bound_of_two`, `sessions_start_in_the_order_they_came_to_wait`, `the_reserve_is_never_a_sessions`, `a_combinations_wait_lapses_thirty_seconds_after_its_last_ask` and `a_part_dropped_unstarted_frees_its_run_at_once`.

True when `cargo test -p sluice --lib host_count -- a_room_counts_an_older_sluices_admission a_new_room_counts_the_runs_still_supervised` passes.
- [x] 2.3 `checks::Checks` holds through a room handle it is bound with: the `Room` itself in the process that holds it, and the host process's socket in any other (task 3.2). `admit` goes. `start` hands its part's hold to the run's supervisor as an admission is handed today, and a session's run takes the part `sluice exec` holds (D12). ## 3. sluice's host process

- [x] 3.1 The hidden command `sluice host` takes `$XDG_STATE_HOME/sluice/host/lock` for its life, and exits at once where another holds it. It writes `host/version` whole and sends its output to `host/log`, keeping the previous log as `log.1`. It binds `host-<digest>.sock` in the user's own short directory (`places::user_dir`, `SLUICE_USER_SCRATCH` in tests), named by a digest of the state folder's real path, after removing a socket a dead process left (135; D1). `crates/sluice/tests/host_process.rs` is added. True when `sluice exec bolt/sluice-runs-one-host-process -- cargo test -p sluice --test host_process -- a_second_host_process_ends_at_once a_socket_a_killed_host_process_left_is_replaced` passes.
- [x] 3.2 `host_process::client` reaches the process, given the program and the state folder. It connects and says `hello` with its version. Where nothing answers, it takes `host/start.lock`, tries once more, and spawns `<program> host` detached: a new session, working folder `/`, stdin null, output to `host/log`, the environment of task 3.3. It polls the socket for ten seconds and fails naming `host/log` where nothing answers. Requests and answers are lines of JSON: `serve`, `step`, `follow`, `pass`, `hold`, `started`, `room` and `hand-over` (D2). True when `sluice exec bolt/sluice-runs-one-host-process -- cargo test -p sluice --test host_process -- ten_reaches_at_once_start_one_host_process a_host_process_that_cannot_start_names_its_log` passes.
- [x] 3.3 `host_process::environment::kept` gives the environment the process starts with. It keeps the run's `KEEP`, `LC_*`, `XDG_*`, `SSH_AUTH_SOCK`, `OTEL_*`, `DOCKER_*`, the `SLUICE_*` settings and git's configuration and prompt variables. It drops `SLUICE_AGENT`, every git variable that names a repository, worktree, index or object store, and a multiplexer session's. The check profile names the development shell's variables it drops (core.1; 135; D3). True when `cargo test -p sluice --lib host_process::environment -- the_host_process_keeps_none_of_its_starters_place the_host_process_keeps_the_hosts_own` passes.
- [x] 3.4 `host_process::index` keeps `host/repositories`, a JSON list of common git directories written whole under `host/start.lock`. `note` adds a repository not yet listed and writes nothing for one listed. The host process drops a listed repository whose directory is gone, or which has no sluice, no records and no policy at any revision the host holds, read as an idle tick reads it (135, 129; D4). True when `cargo test -p sluice --lib host_process::index -- a_repository_is_listed_once a_gone_repository_leaves_the_index a_repository_with_no_sluice_leaves_the_index` passes.
- [x] 3.5 `host_process::pass::pass` is `Command::Run`'s pass, moved whole: the remote's one ask, the abandoned checkouts and unusable previews released, the intake as today, a round of each branch in play, each branch passed by with its words, and the reader's document. It returns a report of the lines it printed and the branches it passed by. `Command::Run` calls it, so nothing changes yet (D5). True when `cargo test -p sluice --test reader_tick -- sluice_run_with_nothing_queued_starts_git_at_its_first_pass_alone` passes, and `cargo test -p sluice --test cli -- a_driver_ends_a_withdrawn_submissions_run_with_nothing_queued a_driver_runs_no_round_for_a_branch_with_nothing_in_play` passes.
- [x] 3.6 The host process reads the index at its start, takes each listed repository with work in play, and serves the requests of task 3.2. Each repository it holds gets a thread with its own `Bound` and the round's retry policy, which runs `pass` at its tick: one second while a watch follows it, three otherwise. It holds the repository's reader lock and its `.driver` lock, and takes an older reader's lease as a newer watch does today. Where an older `sluice run` holds `.driver`, the thread runs no round and follows that run's document. A panic in a thread is caught and logged with the repository, and the thread is started again at the next tick. `check_host_systems` runs at its start, and a host whose systems are wrong claims no run and says so in its log. Under `SLUICE_ROUND_SLEEP=record` it runs a pass only for a `pass` or a `step`, a `serve` holding the repository for the next ask (26, 129, 135; D5, D7, D13). True when `sluice exec bolt/sluice-runs-one-host-process -- cargo test -p sluice --test host_process -- a_served_repository_is_moved_by_the_host_process a_refused_policy_in_one_repository_holds_no_others_round a_repository_an_older_sluice_run_drives_is_left_to_it` passes, and `cargo test -p sluice --lib host_process::tasks -- a_task_that_panics_is_started_again_at_the_next_tick` passes.
- [x] 3.7 The process ends after a tick in which no thread runs, no connection is open, and no part is held or asked for. It decides under `host/start.lock`, after accepting every connection already queued, and then removes its socket. It ends at its next tick once `host/` or its state folder is gone. A thread ends once its repository has nothing in play and nothing follows it, and a repository whose directory is gone is dropped (135; D6). True when `sluice exec bolt/sluice-runs-one-host-process -- cargo test -p sluice --test host_process -- the_host_process_ends_once_its_queues_are_empty the_host_process_ends_with_its_state_folder a_reach_while_it_ends_starts_another` passes.
- [x] 3.8 `hello` answers the process's version. A client whose version is newer, compared as `reader::older` compares, sends `hand-over` once. The process then stops its ticks, lets each thread finish its round and its locks go, and ends. The client then starts its own. A client older than the process uses it, and a request the process does not know is answered with an error naming both versions (D8). True when `sluice exec bolt/sluice-runs-one-host-process -- cargo test -p sluice --test host_process -- a_newer_client_has_an_older_host_process_hand_over an_older_client_uses_a_newer_host_process` passes. The client's version is given to it in the test.
