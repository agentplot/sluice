## 2. sluice run drives one pass at a time

- [x] 2.1 In `crates/sluice/src/lib.rs`, move `run`'s `Command::Run` loop into `pub fn drive(driving: &mut Driving, seams: Seams<'_>, host: &dyn exec::Host, pulls: &dyn PullRequests, clock: &dyn Clock, pause: &dyn Pause, out: &mut dyn Write) -> Result<Driven>`, as design D3 gives it. It runs one pass and its pause, and answers `Driven::Next`, or `Driven::Ended(code)` with the codes the loop exits with today. `Driving::new(rounds: Option<usize>)` holds what the loop carried between passes, and whether the host's systems were checked. `drive` checks them before the first pass it runs, as `run` does today. `run`'s arm loops `drive` until it ends. Nothing a pass does or says changes. True when `cargo test -p sluice --test cli the_first_run_stops` passes.
- [x] 2.2 In `crates/sluice/tests/cli.rs`, beside `the_first_run_stops`, add `a_run_keeps_driving_across_a_new_binding`. #1 is queued on `main` over the fakes. Call `sluice::drive` once with a `Driving` of no bound. Then call it again with the same `Driving`, each time on seams and a host made afresh from the same fakes, until #1 lands. Between any two calls, `Driver::take` of the repository, in the fakes' host's readers, finds it held, and nothing says that another `sluice run` drives the repository. This is the spec's "A pass under a new binding". True when `cargo test -p sluice --test cli a_run_keeps_driving_across_a_new_binding` passes.
