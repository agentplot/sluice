# Tasks

Each group is one session's work for an implementer who reads this
change (proposal, design, specs) and its own group. The groups land in
order, as one landing. Work in this unit's worktree on its branch. Run
suites through sluice (`sluice exec main -- cargo test ...`); a quick
`cargo check` or one unit test may run directly. No test reaches a
remote other than a scratch repository on disk, or a credential
(`support::isolated()`). Commit by pathspec (`git add <paths>; git commit
-m "<subject>" -- <paths>`), Conventional Commits, scoped to the part of
the tree, citing clauses by number and rules by id. Every group ends with
its check task passing. No site page or ADR changes: nothing an operator
configures, reads or runs changes, only what a tick costs.
