# Design

## Context

The site's guides (`site/src/content/docs/guides/`) are ordered by `sidebar.order`: the Claude Code plugin at `-2`, the herdr plugin at `-1`, the walkthrough at `1`, then the rest. The start page and the README both open with the tagline and go straight to installing. Each guide already covers one part of what a newcomer needs, at length: [Parallel and batch](https://agentplot.github.io/sluice/guides/parallel-and-batch/), [Worktrees beside sluice](https://agentplot.github.io/sluice/guides/worktrees/), [The Claude Code plugin](https://agentplot.github.io/sluice/guides/claude-code/). None says what sluice leaves to other tools.

`site:prose` runs Vale with `styles/Sluice` over every page under `site/src/content/docs` except the generated decisions, at `MinAlertLevel = suggestion`, in the gate's fast tier. "Vale reports nothing" therefore means no warning and no suggestion on the new page. The README is outside the site; no gate reads it (core.21, "`*.md` outside the site").

Claude Code makes worktrees itself, by its documentation (https://code.claude.com/docs/en/worktrees): `claude --worktree <name>` starts a session in a new worktree under `.claude/worktrees/`; asked to "work in a worktree" mid-session, Claude creates one; and subagents run in worktrees of their own when asked to or when a custom subagent sets `isolation: worktree`. Background agents' worktrees come from the same mechanism, which is what the newcomer on the call saw.

## Goals / Non-Goals

**Goals:**

- One page a newcomer reads in two minutes that answers "what is this, what isn't it, where do my agents' worktrees come from, and what are batch and parallel", each with a link to the page that says the rest.
- A README a newcomer can't read past without seeing the link.

**Non-Goals:**

- Repeating the guides. The page states each point and links; it holds no configuration reference, no setup steps and no diagrams of its own.
- Any change to the start page, the sidebar's configuration, Vale's styles or vocabulary.

## Decisions

**The page is a guide, first in the sidebar.** File `site/src/content/docs/guides/new-to-sluice.md`, title `New to sluice`, `sidebar.order: -3`, so the autogenerated Guides group lists it above the Claude Code plugin. Its URL is `https://agentplot.github.io/sluice/guides/new-to-sluice/`. A top-level sidebar entry beside "Start" was the alternative; it means editing `astro.config.mjs` for one page, where the guides group already orders by frontmatter.

**Four short sections, in the order the call needed them.** Each heading is a plain sentence-case phrase:

1. *What sluice is.* A CI server for merging agents' work. An agent finishes its work in a worktree and submits it to a branch; sluice tests it on top of everything queued ahead of it and lands only a combination that passed. Each branch's checks are written in `.config/sluice.toml`, under `[branches]`, much as a CI workflow names what runs on a branch, and sluice reads that file from the branch itself, never from a submission. Link: the walkthrough.
2. *What sluice leaves to you.* It is no agent orchestrator: it starts no agents, gives them no work and makes no worktree for an agent. Something else runs the agents (Claude Code, herdr, a crew) and tells each to submit through sluice when its work is done; with the Claude Code plugin installed, Claude knows to. Link: the Claude Code plugin guide.
3. *Where worktrees come from.* Claude Code itself, in the three ways listed under Context, with a link to Claude Code's worktrees page; worktrunk and `git worktree add` work too. The only checkouts sluice makes are its own: one per combination under test and one per preview. Link: Worktrees beside sluice.
4. *Batch and parallel.* Exactly two lines, one per setting, matching the README's quick start:
   - `parallel`: how many combinations a branch tests at once; with `batch = false`, each submission is tested as it arrives, on the bet that those ahead pass.
   - `batch = true`: one combination of everything queued, landed whole when it passes, with a blamed submission looked for only on a failure; for a suite of a quarter hour or more.

   Then one sentence linking Parallel and batch, which also covers the host's `[runs] max` that keeps several agents' suites from swamping one machine.

**The README line goes under the tagline, above the badges.** Inside the centred block, after the "Agents submit…" paragraph: `**New to sluice?** [What it is, and what it leaves to other tools](https://agentplot.github.io/sluice/guides/new-to-sluice/).` The badges are links too; placing the line above them makes it the first link in the README's text. A line at the top of "Get started" was the alternative; a reader skimming the hero would pass it.

**Wording that keeps Vale silent.** The styles that a page like this trips, and how the page avoids each:

- `Sluice.NotXButY` flags "it is not X, it is Y" and "it is not X, but". Say what sluice is in one sentence and what it leaves to others in another ("sluice is no agent orchestrator: it starts no agents…").
- `Sluice.Headings` wants sentence case with only its listed exceptions; "Claude Code" is not one of them, so no heading names it.
- `Sluice.Terms` swaps design words for user words: combination, submission, checkout, result, blamed, never candidate, entry, place, verdict, culprit, and `worktree`, never "work tree".
- `Sluice.Filler`, `Weasel`, `ThroatClearing`, `Hype`, `SoftSales`, `Emphasis`: no "just", "simply", "actually", "really", "usually", "of course", "powerful", "note that". The call's own words are not quoted on the page.
- `Sluice.SentenceLength` at 35 words: the two batch and parallel lines stay well under it.

## Risks / Trade-offs

- [The page drifts from the guides it summarises, a setting renamed or a default changed] → each point is one or two sentences with a link to the guide that owns it, and the batch and parallel lines use the README quick start's own wording, so a change to either is a search away.
- [Claude Code changes how it makes worktrees] → the page names the three ways and links Claude Code's page rather than describing flags in detail.
- [A newcomer on the start page never sees the README] → the sidebar lists the page first among the guides; a start-page link is left to a later change (proposal, out of scope).
